1.  Establecer el Contexto 

Organización: Centro de Investigación, Innovación y Capacitación “Invéntalo”. 

Alcance: Análisis centrado en la seguridad de los sistemas de información que 
gestionan la plataforma web “INVÉNTALO”, destinada a la comercialización integral de 
productos y servicios. Se incluyen los módulos de gestión de usuarios y roles, clientes, 
catálogo de productos y cursos, carrito de compras, pedidos, pagos, ticketing del micro 
museo, generación de reportes y consulta del historial de operaciones por parte de los 
usuarios. 

Contexto Organizacional: El proyecto “INVÉNTALO” consiste en la implementación de 
una plataforma web orientada a centralizar y automatizar la venta de productos 
tecnológicos, la inscripción a cursos y la emisión de entradas para el micro museo 
interactivo. El sistema busca optimizar la gestión administrativa, reducir errores 
asociados a procesos manuales y mejorar la trazabilidad de las operaciones. Asimismo, 
permite a los clientes registrarse, realizar compras o inscripciones y consultar su 
historial de transacciones de manera sencilla a través de una plataforma web accesible. 

Contexto Normativo: El sistema debe garantizar la confidencialidad, integridad y 
disponibilidad de la información, así como la protección de los datos personales de los 
usuarios. Además, debe asegurar la trazabilidad y transparencia de las transacciones y 
reportes generados, en concordancia con los principios de la norma ISO/IEC 27001, 
aunque no contemple integración directa con sistemas contables o fiscales. 

Contexto Técnico: El sistema está implementado bajo una arquitectura web tipo SPA 
con API REST. El backend utiliza Node.js con Express.js y una base de datos MySQL 
gestionada mediante Sequelize ORM. La autenticación se realiza mediante Google 
Console (OAuth) y JSON Web Tokens (JWT). El almacenamiento de archivos se 
gestiona con MinIO y el procesamiento de pagos se integra con la pasarela 
MercadoPago. El frontend está desarrollado con React v18, Vite, TailwindCSS, React 
Router DOM, Axios y tecnologías de visualización 3D. 

Criterios de Riesgo: Se consideran riesgos Críticos aquellos que podrían ocasionar la 
interrupción total del servicio, fraudes en pagos, acceso no autorizado a información 
sensible, pérdidas financieras significativas o daño severo a la reputación de la 
organización. Los riesgos Altos implican interrupciones importantes del sistema o 
vulneraciones de seguridad con impacto considerable. Los riesgos Medios pueden 
generar fallas temporales, reprocesamientos o inconsistencias limitadas en la 
información. Los riesgos Bajos tienen un impacto mínimo en las operaciones. La 
evaluación de riesgos se basa en una metodología cualitativa que considera el impacto 
y la probabilidad de ocurrencia. 

 
2.   Identificación de Activos 

Para la Plataforma Web de Comercialización Integral de “INVÉNTALO”, los 
siguientes 23 activos son cruciales: 

Activos de Información 

1.  Base de Datos de Usuarios, Ventas y Operaciones (MySQL): Contiene datos 

sensibles de usuarios/clientes, productos/cursos, pedidos, pagos, tickets, 
inscripciones e historial/auditoría. 

2.  Servidor de Aplicaciones (Infraestructura Cloud): Entorno de ejecución que 
aloja el backend (Node.js/Express) y expone la API REST que procesa la lógica 
de negocio. 

3.  Repositorio de Objetos (MinIO): Almacena archivos e imágenes (productos, 

recursos de cursos y/o adjuntos operativos), asegurando disponibilidad y control 
de acceso. 

4.  Interfaz de Usuario: Panel de Administración: Permite a los administradores 
gestionar usuarios/roles, catálogo, stock, pedidos, pagos, cursos, tickets y 
reportes. 

5.  Interfaz de Usuario: Catálogo y Compra: Vista para que los clientes exploren 

productos, gestionen el carrito y generen pedidos. 

6.  Interfaz de Usuario: Cursos e Inscripción: Módulo para que los clientes 

visualicen cursos/talleres y registren inscripciones. 

7.  Interfaz de Usuario: Ticketing del Micro Museo: Módulo para compra/consulta 

de entradas y control del estado del ticket (vigente/usado/anulado). 

8.  Credenciales de Acceso y Tokens (OAuth/JWT): Nombres de usuario y 

contraseñas (hasheadas), tokens JWT y credenciales OAuth de Google (activos 
críticos de seguridad). 

Activos Físicos 

9.  Infraestructura de Servidores en la Nube: Servidores físicos del proveedor 

cloud que alojan la aplicación, la base de datos y MinIO, asegurando operación 
continua. 

10. Estaciones de Trabajo de Desarrollo (Laptops/PC): Equipos del equipo 

utilizados para codificar, probar, administrar y desplegar la plataforma; contienen 
código y credenciales. 

11. Equipos de Operación (Administración/Soporte): Dispositivos usados por el 

rol administrador para gestionar pedidos, pagos, stock y reportes. 

12. Equipos de Red Local (Routers/Switches): Dispositivos que proporcionan 
conectividad a internet para administrar los servicios en la nube y acceder al 
panel. 

Activos de Software 

13. Aplicación Web “INVÉNTALO”: Sistema principal que gestiona catálogo, 
carrito, pedidos, pagos (MercadoPago), cursos, tickets, reportes e historial. 

14. Código Fuente del Proyecto: Conjunto de archivos del frontend y backend que 
componen la aplicación y representan la propiedad intelectual del proyecto. 

15. Framework/Librerías Frontend (React v18 + Vite + TailwindCSS): 
Tecnologías sobre las que se construye la interfaz del cliente (SPA), 
enrutamiento y experiencia de usuario. 

16. Runtime/Framework Backend (Node.js + Express.js): Tecnologías sobre las 

que se construye la API REST y la lógica de negocio del sistema. 

17. ORM Sequelize: Herramienta para la gestión de modelos, validaciones y 

operaciones sobre la base de datos MySQL. 

18. SGBD MySQL: Motor de base de datos relacional utilizado para almacenar de 

forma persistente y segura la información del sistema. 

19. Integración de Pagos (MercadoPago): Servicio y componentes de integración 

(incluyendo confirmación vía backend/webhooks) para procesar pagos y 
actualizar estados de pedidos. 

Activos de Personal 

20. Líder de Proyecto / Desarrollador Principal: Responsable de la supervisión 
general, decisiones técnicas, seguridad base, despliegue y mantenimiento del 
sistema. 

21. Equipo de Desarrollo y Soporte: Miembros con roles de backend, frontend, 

base de datos, QA/pruebas, UI/UX y documentación. 

22. Rol “Administrador/Gestor”: Usuario con permisos elevados para administrar 

catálogo, stock, pedidos, pagos, cursos, tickets y reportes. 

23. Usuarios Finales (Clientes): Usuarios externos que realizan compras, se 

inscriben a cursos, adquieren tickets y consultan su historial (principal fuente de 
datos personales y transacciones).

4.  Metodología para la Valoración de Riesgos 

a.  Determinación del Impacto 

El impacto representa la magnitud de las consecuencias que se producirían si 
una amenaza llegara a materializarse sobre los activos del e-commerce. Se 
evalúa en función de la afectación a la confidencialidad, integridad y 
disponibilidad de la información, así como del impacto operativo, financiero y 
reputacional.

7.  Monitoreo y Revisión 

El monitoreo continuo es esencial para detectar desviaciones, evaluar la 
efectividad de los controles de seguridad implementados y asegurar la 
disponibilidad, rendimiento e integridad del e-commerce “INVÉNTALO”. 

•  Disponibilidad del Servicio (RNF-Disponibilidad): 

o  Métrica: Tiempo de actividad (uptime) del e-commerce y de la API 

REST. 

o  Objetivo: > 99.9% de uptime mensual. 
o  Herramienta: UptimeRobot y monitoreo nativo del proveedor cloud. 

•  Rendimiento de la Plataforma (RNF-Rendimiento): 

o  Métrica: Tiempo promedio de carga de las vistas más utilizadas 
(Login, Catálogo, Carrito, Checkout, Panel de Administración). 

o  Objetivo: < 2 segundos por vista en condiciones normales. 
o  Herramienta: Google Lighthouse (auditorías periódicas), 

herramientas de monitoreo de frontend (ej. Sentry) y métricas del 
servidor Node.js. 

• 

Integridad de Datos y Operaciones (RNF-Integridad): 

 
o  Métrica: Porcentaje de pedidos, pagos e inscripciones procesados 

correctamente sin reprocesos. 

o  Objetivo: > 98% de operaciones exitosas. 
o  Herramienta: Logs del backend (Node.js/Express), registros de 

transacciones y validaciones en base de datos MySQL. 

•  Seguridad de Autenticación y Acceso (RNF-Seguridad): 

o  Métrica: Número de intentos fallidos de inicio de sesión por usuario 

en un período de 24 horas. 

o  Objetivo: < 5 intentos fallidos por usuario. 
o  Métrica adicional: Detección de accesos inusuales (múltiples IPs, 

ubicaciones o dispositivos en corto tiempo). 

o  Herramienta: Logs de autenticación (JWT/OAuth), análisis de logs 

del backend y alertas de seguridad. 
•  Uso de Recursos del Sistema (RNF-Capacidad): 

o  Métrica: Uso de CPU y RAM del servidor de aplicaciones. 
o  Objetivo: Mantener el uso promedio por debajo del 70%. 
o  Herramienta: Dashboards del proveedor cloud y monitoreo del 

runtime Node.js. 

o  Métrica adicional: Crecimiento del almacenamiento de base de 

datos MySQL y del repositorio de objetos MinIO. 

o  Objetivo: Monitorear crecimiento y proyectar capacidad para evitar 

saturación.
